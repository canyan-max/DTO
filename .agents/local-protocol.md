# 统一本机协议：UART1／UART2／UART3

2026-10-20 按用户要求将参数、继电器、版本、模式合并为一套本机协议。
唯一解析/校验/组包文件：Protocols/proto_local.c/.h。
原proto_params、proto_dto四个文件及MDK构建项已移除，不保留两级分发。

## 入口和执行

- 本机地址固定0x14，Modbus RTU CRC16，CRC低字节在前，寄存器值高字节在前。
- UART1（4G）、UART2（485口1）、UART3（485口2）均支持完整本机协议，
  DTO和采集模式相同；回复从接收请求的原端口发出，不广播本机回复。
- App/app_local统一应用请求，App/app_dto或app_hik仍是当前模式唯一RX消费者。
  本机请求优先分发，再处理AT配置、海康或控制器回复/透传。
- 当前只允许一个本机事务执行，其余端口完整请求留在各自队列等待；不覆盖正在发送的回复。
  Flash/4G配置及模式切换维护期间暂停业务，维护窗口内输入可丢弃，结束后重试。
- 用户已将0x14指定为本机地址；其他从机地址在DTO中保持透传。
  旧版“两路485只支持模式34”的限制现已取消。

## 连续寄存器表

下表地址是十进制。03可读取17～43任意合法连续子区间，最大27项/59字节回包。

| 地址 | 含义 | 写入方式 |
| --- | --- | --- |
| 17 | 继电器1有效逻辑输出 | 05：FF00逻辑1，0000逻辑0 |
| 18 | 继电器2有效逻辑输出 | 同上 |
| 19、20 | 继电器1、2输出的反向只读别名 | 只读，非继电器3、4 |
| 21～25 | 10字节软件版本字段 | 只读，DTO_V2.0.0或HIK_V2.0.0，随模式变化 |
| 26 | 欠压保护阈值，mV | 06，非0且小于恢复阈值 |
| 27 | 欠压恢复阈值，mV | 06，大于保护阈值 |
| 28 | 欠压使能 | 06：0/1 |
| 29、30 | 485口1波特率，高/低16位 | 10，必须成对写 |
| 31、32 | 485口2波特率，高/低16位 | 10，必须成对写 |
| 33 | 一次性保存/默认恢复命令，读为0 | 06：56781保存、52445恢复默认 |
| 34 | 当前模式 | 06：0 DTO、1 HIK采集 |
| 35 | 两路继电器接线配置 | 06：bit0继电器1、bit1继电器2；0常闭、1常开 |
| 36 | 电池电压 | 只读，0.01V |
| 37 | 电池电流 | 只读，有符号，0.01A |

| 39 | 剩余容量 | 只读，0.01Ah |
| 40 | 标称容量 | 只读，0.01Ah |
| 41 | 电池温度1 | 只读，有符号，0.1℃ |
| 42 | 太阳能电压 | 只读，0.01V |
| 43 | 太阳能电流 | 只读，0.01A |

兼容旧功能01：17～20一项一个字节，保留旧布局，不改成标准位打包。
10支持从29写2项/4项，或从31写2项；不支持其他批量写入范围。
CRC错误或不完整帧无回复；合法本机帧的非法地址、功能或值返回Modbus异常。
输出容量按实际帧长度检查，协议不直接访问UART、GPIO或Flash。

## 参数和继电器保存规则

- 参数26～32及接线35修改RAM，模式34安全切换后才更新RAM，均不自动擦Flash。
- 任一端口写33=56781：原口ACK、三路TX完成后暂停RX，原单页保存并验证，
  成功后重启；失败恢复接收并计失败，不自动反复擦写。
- 任一端口写33=52445：沿用同样维护流程，写入默认参数、DTO模式及接线35=0后重启。
- 修改波特率只改RAM；保存后下次启动生效，不在回复途中改变当前波特率。
- 继电器请求仍自动保存到原继电器页；等待原口ACK及三路TX完成，不重启。
  欠压保护只覆盖输出，不改写用户请求；模式切换保持公共状态。
- SN仍仅HIK协议RAM缓存，不加入本机寄存器，也不随56781保存；真正重启会清空。

| 继电器1逻辑0 | `14 05 00 11 00 00 9F 0A` |
| 切DTO | `14 06 00 22 00 00 2B 05` |
| 切采集 | `14 06 00 22 00 01 EA C5` |
| 读模式 | `14 03 00 22 00 01 26 C5` |
| 保存参数并重启 | `14 06 00 21 DD CD 43 C0` |

操作前停同一总线上的周期发送，按一问一答测试；串口保持现有保存波特率。
切换ACK后等至少1秒并确认模式，再发业务/保存；不要把 `14 03 02 ...` 读回复当作请求。
建议先在每个端口读取全表、再单独测试继电器和参数RAM修改，最后显式保存并断电复读。
采集模式的485口2有主动轮询，调试指令应避开正在发送的查询/设备应答。

## 接线配置与采集数据说明

35使用两个位，合法值0/1/2/3，默认0。GPIO电平=有效逻辑输出 XOR 接线位。
有效逻辑输出是经过欠压保护覆盖的状态，保护时仍强制逻辑0，再统一映射GPIO；
恢复后重新使用记忆的逻辑请求。相同控制值在两种接法下保持相同触点连接语义。
修改35只改变物理映射，不改记忆请求、不清欠压计时、不自动保存继电器页。

Watch中g_relay.requested是用户逻辑请求，output是保护后的逻辑状态，gpio是实际电平。
协议17/18读output、19/20读其反向别名；配置0时与旧版读数/GPIO完全一致。

例如两路逻辑均0：35=0时GPIO均0；35=1时GPIO为1/0；35=2时GPIO为0/1；
35=3时GPIO均1。逻辑均1时相反。35用56781显式保存，未保存重启回已保存值。
配置保存在参数单页24字节记录第二个64位字bits48..55；bits56..63必须0。
原有效记录该字节0，所以保留原参数且默认常闭；旧固件可能不识别非0的新接线记录。

36～43来自svc_telemetry有效外部控制器快照，两路独立7秒过期；过期/切模式/
无有效采集时对应测量值回0。DTO不主动采集，切换后的缓存无效时读0是预期行为。
39剩余容量按用户确认，以标称容量×SOC/100估算（0.01Ah单位，向下截断），
由svc_poll统一写入共享缓存，本机与HIK回复一致。容量缺失或SOC为0时结果0，
例如200Ah×88%=176Ah，寄存器17600（0x44C0）。41由旧HIK温度单位
减2731换成有符号0.1℃，NTC数量0或温度超出寄存器有符号范围时回0。
本机ADC保持独立，不替代外部电池电压；采集只读寄存器不写Flash。
