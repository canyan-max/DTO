# DTO 收尾：继电器、欠压、版本与指示灯

2026-10-20更新：本机协议已统一为proto_local，UART1/2/3均支持完整17～34寄存器，
包括参数/继电器/模式/保存；原口回复。旧入口限制和proto_params/proto_dto说明
仅为历史，当前以 [统一本机协议](local-protocol.md) 为准，新功能上板待验。

## 硬件和输出约定

- 用户确认只有继电器 1、2，3、4 已移除。BSP 拒绝操作下标 2、3；Core/IOC
  保留用户生成配置，不批量改引脚初始化。
- 无有效记忆时保持 CubeMX 的两路 GPIO 低电平：线圈不吸合，NC 闭合、NO 断开。
  有有效记忆则在应用启动时恢复；协议状态 0/1 表示 GPIO 低/高，不表示负载通断。
- 接线配置现已按35的bit0/bit1实现NC/NO选择。保护动作定义为逻辑0后统一映射GPIO，
  不能将其解释为所有接线方式下都断开负载。

## 本机协议

入口仍为 UART1，地址 0x14；两路 485 不新增同口响应。

| 地址 | 读取含义 | 写入 |
| --- | --- | --- |
| 17 | 继电器 1 实际 GPIO 状态 | 功能 05：FF00=高，0000=低 |
| 18 | 继电器 2 实际 GPIO 状态 | 同上 |
| 19 | 继电器 1 状态取反，沿用旧映射 | 只读，第 3 路控制不存在 |
| 20 | 继电器 2 状态取反，沿用旧映射 | 只读，第 4 路控制不存在 |
| 21～25 | 10 字节 ASCII 版本 DTO_V2.0.0 | 只读，配置在 dto_config.h |
| 26～33 | 原有保护参数/波特率/保存控制 | 沿用 proto_params |

- 功能 03 支持连续读 17～33，包括跨版本和参数段；未知地址不填假数据。
- 功能 01 仅读 17～20，保留旧版“一项一字节”布局，不是标准 Modbus 的位打包。
- 功能 05 仅接受 17、18 和 FF00/0000；写 19、20 返回异常 02，非法值返回 03。
- CRC 错误和短包不执行、不回复、不广播。不支持的 SN/升级不伪造成功。

## 状态保存

- 用户授权继续使用原继电器页 0x0801F000，只擦该 2 KiB 页，写首个 64 位字。
  兼容旧 0～15 四位记录，只恢复最低两位；新写入只保存 0～3。
- 全擦除/无效记录不自动写 Flash，默认保持低；合法 0 记录可正确恢复。
- 有效继电器指令立即更新请求/GPIO，回包完成且三路 TX 排空后暂停三路 RX，
  保存并回读校验，恢复 RX 和 DTO。自动保存，无需另发保存口令，也不重启。
- 相同的两路状态跳过擦写；单页中断可能丢失记忆，无法校验的记录回低默认。
  沿用旧单字位图，没有增加双页或改变参数页格式。
- 回包仅代表请求被接受；最终保存须查看状态或断电复测。回包失败不保存，
  Flash 失败保留当前请求、dirty=1，恢复通信，不自动反复擦写。重发控制指令
  可再次尝试保存。恢复默认参数口令仍只作用于参数页，不清继电器页。

## 欠压与灯

- 使用现有寄存器 26/27 阈值与 28 使能；默认使能仍为 0。
- 有效 ADC 电压连续 <= 保护阈值 3 s 后，两路 GPIO 强制低。
- 保护中有效电压连续 > 恢复阈值 3 s 后，恢复最新请求状态。
- 保护中允许控制指令，记住并保存请求，但输出保持低；保护与恢复不自动
  改写 Flash。不会强制把原来请求为低的继电器恢复成高。
- 修正旧定时流程“先保护置低，后续分支再置高”的冲突。3 s 用毫秒计时，
  不沿用旧恢复计数 >3 带来的额外一拍。
- 无效/过期 ADC 不以 0V 处理，不解除已进入的保护，清空连续计时；调度长
  时间中断也重新计时。关闭保护使能则立即解除覆盖并恢复请求输出。
- 保护仅影响继电器和指示灯，不关闭 4G/485 电源，通信继续运行。
- 工作灯每 1 s 翻转，两路通信灯在收到字节后亮约 100 ms；保护时三灯熄灭。

## 上板步骤

手动下载 MDK-ARM/comm_convert/comm_convert.hex。UART1 HEX 发送，指令之间
留至少 200 ms，等待控制回包与维护窗口完成。

| 操作 | 完整命令（含 CRC） |
| --- | --- |
| 继电器 1 GPIO 高 | `14 05 00 11 FF 00 DE FA` |
| 继电器 1 GPIO 低 | `14 05 00 11 00 00 9F 0A` |
| 继电器 2 GPIO 高 | `14 05 00 12 FF 00 2E FA` |
| 继电器 2 GPIO 低 | `14 05 00 12 00 00 6F 0A` |
| 读取两路状态及反向别名 | `14 03 00 11 00 04 16 C9` |
| 读取版本 | `14 03 00 15 00 05 96 C8` |
| 连续读 17～33 | `14 03 00 11 00 11 D7 06` |
| 旧 01 状态读取 | `14 01 00 11 00 04 6F 09` |
| 启用欠压保护（先仅 RAM） | `14 06 00 1C 00 01 8B 09` |
| 关闭欠压保护（先仅 RAM） | `14 06 00 1C 00 00 4A C9` |

1. 先控制 1、2 高/低，核对 GPIO 和触点，05 应原样回复；读取 17～20 时
   例如两路低应为 0000、0000、0001、0001，两路高应为 0001、0001、0000、0000。
2. 设定一高一低，等待至少 1 s，断电再上电，核对恢复相同状态；不要重新
   下载程序作为掉电测试。此步骤不需要参数保存口令。
3. 保护测试前读 26/27，确认实际阈值（此前用户保存过 10500/12000）。
   先设两路高、启用保护，将输入维持在保护阈值以下约 3 s，两路应低；
   恢复到恢复阈值以上约 3 s，两路应恢复请求状态。期间应能查询/转发。
4. 保护期间将其中一路请求改低，电压恢复后该路仍低，另一请求高的路恢复高。
5. 试验后可关闭保护；如需使能状态掉电保持，再使用原参数保存/重启指令。

观察 Services/svc_relay.c 的 g_relay：requested 是记忆请求，output 是实际
GPIO 状态；uv_active 为保护状态，dirty 为尚未保存，from_flash/saves/failures
反映保存结果。App/app_local.c 的 g_local_status 反映回包/维护流程。
