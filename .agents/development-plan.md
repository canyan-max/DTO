## 开发顺序

先开发公共串口收发，用 DTO 验证三路完整数据路径，再迁公共配置与采集业务。
ADC 放在通信主路径之后；Flash/升级先定布局再实施。
每阶段独立编译与验收，不一次搬入两套 main、回调和全局变量。

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| 1 | 六层结构、最小 App、IO/电源、喂狗、三路 UART BSP 与收发服务 | 正确接入 Keil；独立收发、超时和溢出可观察；0 error/0 warning |
| 2 | DTO 双路下发、两路回复排队送 UART1 | 二进制原样通过；同时回复不覆盖、不交叉；忙与队列满有明确处理 |
| 3 | 4G 配置、旧本机指令分类、模式入口 | 经确认的 485 入口可反复配置；AT 应答不混入业务 |
| 4 | 参数存储及必要兼容接口 | 先定 Flash/Bootloader 布局；验证校验、掉电恢复和失败处理 |
| 5 | 非 DMA ADC、滤波、电压读取 | 不依赖 DMA；等待有界；原始值与单位明确；与实测电压比对 |
| 6 | UART3 协议/轮询/缓存，UART2 海康查询响应 | 明确离线、超时、缓存有效性和寄存器映射，复用公共继电器服务 |
| 7 | 统一模式选择/切换与整机回归 | 两模式分别可用；选择规则确认；切换不遗留事务或错误缓存 |

阶段 1 同时梳理旧指令与地址，区分“DTO 数据路径通过”和“全部旧功能兼容”。
阶段 2 不代表 4G 配置、参数、升级和采集已经可用。
如 4G 测试依赖配置，先用有线串口验 DTO，再接阶段 3。

## 第一阶段具体任务

1. Config/ 定义端口角色与有源码依据的默认参数，不凭空增加模式指令。
2. Bsp/ 封装 UART 中断收发、错误恢复、GPIO/电源，保持无 DMA 和硬件 DE；
   继电器按确认需求处理，不先搬旧持久化恢复。
3. Services/ 管理独立 RX/TX 缓冲、帧长、最后收字节时刻、发送队列、
   错误/丢弃计数；每个新字节重置帧间静默计时。
4. App/ 提供有限执行时间的 init/task，主循环处理后喂狗；
   Core USER CODE 区接入接口，每类 HAL 回调只有一个实现。
5. 新源码和包含路径接入根目录 MDK，保持重新生成的边界。
6. 编译并准备三路收发验收；上板结果需用户提供或在明确授权烧录后验证。

## DTO 约束与验收

- 广播前确认两路队列均可接纳，避免只发一路；两路入队不承诺引脚同时起发，
  要求是两路收到同一份数据。
- 两路回复各自完整缓存，UART1 逐项发送；跨端口无天然绝对顺序，
  选择稳定排队策略并记录。原样转发不附加来源标签。
- 明确最大帧长和静默间隔；透明字节流与静默分帧不能混称。
  对连续超长输入、上游速率超过下行容量定义可观察的失败策略。
- 验证单路/双路同时回复、连续查询、二进制零字节、边界长度、超长包、
  队列满和串口错误恢复；逻辑测试与上板结果分别记录。
- 旧超时、容量和 ADC 换算值均不当作用户已确认的新参数。

## 模式与升级边界

- 首个模式可经内部接口单独验证；默认模式及持久化选择实现前确认，
  未实现的采集模式不开放为可用选项。
- 如需在线切换，停止新事务、结束/终止当前发送、清理接收与协议状态，
  再配置并启动目标模式；处理超时和失败返回。
- Bootloader 升级单独实施：确认现有 Bootloader、应用地址、向量表、
  参数页与链接长度，第一批不启用旧地址擦写及跳转。
