# 第一阶段：公共串口收发

后续进度：第二阶段已接入 DTO，当前构建启用路由。下文“没有业务消费者”等
描述保留第一阶段历史状态；当前测试以 [DTO 说明](dto-bringup.md) 为准。

## 已接入范围

- `Core/Src/main.c`：USER CODE 区调用 `app_init()`、`app_task()`，失败进入
  原 `Error_Handler()`；主循环正常处理后喂 IWDG。
- `Bsp/bsp_system`：毫秒时间、保存并恢复 PRIMASK 的短临界区、喂狗。
- `Bsp/bsp_io`：4G/两路 485 电源使能和四路继电器接口。
  上电使能电源与旧 Program 一致，继电器保持新 CubeMX 生成的默认低电平；
  未读取旧继电器 Flash 状态，实际控制极性和连线尚需上板验证。
- `Bsp/bsp_uart`：三路逐字节中断接收、中断发送、统一 HAL 回调；RX 错误
  关中断后交主循环恢复，TX 完成以 HAL 的 TC 回调为准。
- `Services/svc_serial`：每端口独立的静默分帧、RX 帧队列、复制式 TX 队列、
  边界校验及诊断计数。
- `Config/comm_config.h`：端口角色与第一批资源参数；波特率宏仅记录现有
  CubeMX 配置，不会覆盖 `Core/Src/usart.c`，实际配置仍以 IOC/生成代码为准。
- Keil 已接入 App、Bsp、Services、Config 分组和六层包含路径；Protocols
  暂无业务源码。

当前仍未启动 DTO、采集模式、4G AT 配置、参数写 Flash、Bootloader、ADC
采样或 TIM14/TIM16 周期任务。没有定义默认业务模式或添加切换命令。

## 接口与缓冲区归属

业务只在主循环上下文调用 `svc_serial_send/read/get_stats`，不从 IRQ 调用。
`svc_serial_task()` 持续运行；初始化只能调用一次，启动失败按致命错误处理。
UART IRQ 通过已注册回调将字节交服务层，底层不反向引用 App 或 Services。

| 接口 | 语义 |
| --- | --- |
| `svc_serial_send(port, data, length)` | 数据复制入队；OK 表示已入队，不表示线上发送成功 |
| `svc_serial_read(port, data, capacity, length)` | 取出最早完整帧；EMPTY 时 length 为 0 |
| `svc_serial_read` 返回 BUFFER_SMALL | length 为所需容量，原帧保留，可换大缓冲重读 |
| `svc_serial_get_stats(port, stats)` | 拷贝端口诊断快照，不返回内部可写指针 |

- RX 每路最多保留 4 个完整帧，另有一个正在组帧的独占槽；完整帧被消费前
  不会被 IRQ 覆盖。帧数据拷贝不放在关中断区内。
- TX 每路 4 个槽，含正在发送的帧；服务层独占 TX 缓冲，调用方入队后可复用
  原始数据。满时返回 FULL，不覆盖已排队数据。
- 当前最大帧长 256 字节，UART1 静默 15 ms、UART2/3 静默 50 ms 分帧。
  这些是沿用旧值作为迁移起点，尚未完成实际流量调优。
- 每个新字节重置静默计时；主循环未及时执行时，下一个字节也可按时间间隔
  封存前一帧。毫秒差使用无符号减法，支持计时器回绕。
- 超过 256 字节时丢弃整帧，持续接收并等到静默再重新组帧，不上交截断包。
  RX 完整帧队列满时丢弃新完成帧，保留旧帧。计数可通过统计接口读取。
- RX 错误或重装接收失败会使当前帧失效；主循环立即尝试恢复，失败后每
  10 ms 重试，恢复后继续丢弃到下一静默边界。此前完整帧仍保留。
- 发送超时按实际 UART 波特率、8N1 的 10 bit/byte 线速计算，再加 100 ms。
  超时中止后记录错误，不自动重发可能已部分发送的请求；中止失败则保留
  缓冲继续尝试，禁止复用仍可能被 IRQ 读取的缓冲。
- 开始发送持续 BUSY 时最多等待 1000 ms，随后将该队列项记为失败。

这里是按静默分帧的有限缓存服务，不承诺无限连续字节流或任意速率无损转发。
现有 CubeMX RX overrun disable 配置保持原样，硬件丢字节和实际时序仍需实测。

## 验证结果

- ARM Compiler 5.06 update 6 构建：0 error、0 warning。
- 程序 Code=18128、RO=408、RW=24、ZI=9520 字节；总 ROM 18560 字节，
  总 RW/ZI 9544 字节（包括链接输出中的栈/堆保留）。
- `.agents/tests/test_serial.py` 使用本机 GCC 编译实际 UART BSP 和收发服务，
  用假 HAL 驱动 13 个场景：初始化、逐字节静默重置、IRQ 分帧、256/257 字节
  边界、队列满/回绕、小缓冲/非法参数、RX 错误/恢复重试、TX 顺序/缓冲复制、
  TX 超时/中止重试、启动持续忙、毫秒回绕、三路独立收发、接收重装失败。
- 主机测试同时检查临界区保留原来的关中断状态。运行：
  `python -X utf8 .agents/tests/test_serial.py`，需要原生 GCC，不使用 ARM GCC。
- 用户已手动上板确认三路均能收到数据，基本接收通过；代理未执行烧录。
  发送、DTO 转发、真实 DE 发送时序、设备响应和满速稳定性尚待上板验证。

## 上板验收与下一阶段

当前 App 没有业务消费者：接收帧保留在队列中，不会自动回显或转发；持续灌入
超过队列容量时出现 rx_queue_full 是预期行为。可在 Keil 查看
`svc_serial.c` 的 `g_ports` 和 `bsp_uart.c` 的 `g_devices`，后续通过服务 API
接入业务后再做完整链路收发验收。

下一步实现 DTO 的应用层路由，先确保两路队列都能接纳同一条下发，再投递；
UART2/3 回复各自保留，统一排队发 UART1。仍需明确最大业务长度与旧本机命令
拦截兼容范围，不能把仅数据路径完成描述为旧固件全部功能完成。
