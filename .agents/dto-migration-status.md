# DTO 迁移范围核对

更新：2026-10-19。对照参考 Program 实际调用链，不把基本透传通过等同旧固件全功能兼容。

| 功能 | 当前结果 |
| --- | --- |
| UART1 同帧下发 UART2、UART3 | 用户确认通过 4G 下发可转发两路 485 |
| UART2、UART3 回复排队返回 UART1 | 用户确认平台可收到两路信息；严格同时回复等边界有主机测试 |
| 两路 485 触发旧 21 步 GM800 配置 | 两口均由用户验证，平台上线；仍无模块应答确认机制 |

| 恢复默认、两路波特率保存后启动应用 | 已实现且主机测试通过，上板待验 |

| 两路继电器控制及原页状态保持 | 用户确认控制及掉电记忆正常 |
| 欠压覆盖及恢复请求状态 | 用户确认保护触发及电压恢复正常 |
| 版本读取和 LED 指示 | 已实现、模拟测试通过，待上板 |

## 本轮收尾范围

- 用户确认仅继电器 1、2，默认低，3、4 移除。17/18 控制两路，19/20 仅保留
  反向读取别名；旧 01 布局保留。继电器自动保存到 0x0801F000，恢复默认参数
  不清除继电器状态。常开/常闭配置按用户要求暂不做。
- 21～25 读取新版本 DTO_V2.0.0；工作灯心跳与两路 RX 活动指示已接入。
- 欠压保护和恢复采用 3 s 连续有效采样，保护强制两路低，恢复最新请求状态，
  不改写记忆；修正旧流程保护后又置高的冲突。详细行为及实测命令见
  [DTO 收尾测试](dto-relay-bringup.md)。

## 独立待定范围

- 0x42 升级入口：未迁入；当前无已确认 Bootloader，应用起始地址与旧版不同。
- 旧文件虽有 SN 定义，但 Program 当前寄存器组包没有有效填充 SN；不能按
  定义或 app-demo 的实现就认定 Program 此路径已有可用 SN 功能。

## 仍待上板验证

- 两路同时回复、连续/长帧、拥堵与错误恢复的整机测试；主机模拟已有覆盖。
- 参数恢复默认、两路波特率保存生效。
- ADC 同时运行时的 DTO 通信回归，未单独收到反馈。
- 版本和灯未单独反馈，保护中改指令和使能保存后的掉电保持未单独反馈。

## 后续方向

- 用户已确认欠压恢复、继电器掉电记忆和 4G 双路通信，DTO 本轮约定功能
  验收通过；不表述成所有旧指令/升级和整机压力测试已经通过。
- 采集模式主机侧用户已选择先接海康专用协议；这不同于地址 01/08 的 Modbus
  查询。轮询侧首个控制器类型尚未选择，不把这次回答记为选定汇能。
- 本轮未切换模式、未接入轮询；在 DTO 上补齐上述本机控制/保护行为。
