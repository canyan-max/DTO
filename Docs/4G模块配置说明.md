# GM800配置与查询说明

更新：2026-10-20。两种模式共用23步配置流程，支持逐条应答和原485口日志。

## 发起方式

在任一485口ASCII发送`AT+CLOUD=`后接20位数字，可附旧后缀及CRLF。
仅使用此次请求中的设备编号；鉴权后缀按现有已确认配置组包，不默认使用旧设备身份。
UART1不作为这个配置请求入口。串口使用当前有效波特率，出厂485为9600、8N1。

两路485在DTO/HIK均支持。配置先排空现有发送并暂停普通业务，不在上电时自动重配。
重复请求及本机保存/恢复默认等维护期间输入会被丢弃，不排队；结束后重发。

## 流程与应答

| 步骤（从1计数） | 操作 | 应答 |
| --- | --- | --- |
| 1 | +++，不带CRLF | a |
| 2 | a，不带CRLF | 完整+ok行，兼容回显形成a+ok |
| 3～18 | 旧网络、连接、心跳、注册及CLOUD配置 | 完整OK行 |
| 19 | AT+ICCID?\r\n | 数据可先返回，仍等待完整OK行 |
| 20 | AT+IMEI?\r\n | 数据可先返回，仍等待完整OK行 |
| 21、22 | 两次AT+S\r\n保存 | 完整OK行 |
| 23 | AT+Z\r\n重启模块 | 完整OK行 |

上表\r\n表示实际字节0D 0A。保持相邻起发至少200ms，同时等待前条发送完成、应答通过。
超时从观察到UART1 TX完成起算：普通/握手2s，保存各5s，整个会话最多90s。

解析支持串口分段、多行合帧，128字节行缓冲；回显、编号、NOTOK和启动标识不当作OK。
ERROR、ERR、+ERR均失败，同批错误优先；UART错误、帧溢出或丢帧也终止后续操作。
失败不自动重试或重新配置，不因应答失败重启MCU；由外部重新发配置请求，从头执行。
已被模块接受的部分配置不回滚。

## 日志及结果

- 模块原始回复只发回配置发起口，保留编号、回显、CR/LF及分段。
- 日志使用非阻塞队列，满则丢日志，ACK解析不受此影响。
- 成功/失败均收尾接收500ms，之后停止新增原始日志，排空TX并发送最终提示后退出。
- 成功提示：`[GM800] CONFIG CONFIRMED`。
- 失败示例：`[GM800] FAIL step=20 ERROR; SEND CONFIG AGAIN`。
- CONFIRMED只代表全部23条应答通过，不是平台上线或参数回读验证。
- ICCID/IMEI仅原样打印，不新增本机寄存器、编号缓存或Flash存储。

诊断：`svc_gm800_get_status`中的commands_sent、commands_confirmed、failed_step、
log_frames、log_dropped、failures；成功commands_confirmed＝23，失败编号1～23。
旧SENT_UNVERIFIED枚举保留但不再作为本流程成功终态。
