# XDZ模式（第三种模式，寄存器34＝2）

日期：2026-10-21。版本字段为`XDZ_V2.0.0`，默认启动模式仍为DTO。
参考`app - 副本/User/Commlib`中的`comm_jbd_master`和`comm_fky_lib`及其串口分工；
不迁移参考工程的`comm_rs485_slave.c`，不修改参考工程，也不修改Boot。

## 端口与层次

| 接口 | XDZ职责 |
| --- | --- |
| UART1／4G | 本机0x14配置，不透传XDZ业务 |
| UART2／485口1 | 主动轮询电池，地址05、功能03 |
| UART3／485口2 | 等待外部主机查询，地址02、功能04；功能10控制继电器 |

与HIK的设备口／主机口相反。两路波特率仍由本机29～32的参数决定，默认9600、8N1。
本机0x14、BootLoad、两路485的AT+CLOUD均通过现有公共入口处理。
Protocols/proto_xdz只编解码；Services/svc_xdz_poll单事务采集；App/app_xdz独占RX分发。
模式互斥、排空TX后等连续700ms静默再切换；继电器、保护、参数及RAM SN继续共用。

## 快速测试（HEX，CRC已包含）

| 操作 | 指令／位置 |
| --- | --- |
| 任意口切到XDZ | `14 06 00 22 00 02 AA C4` |
| 读模式 | `14 03 00 22 00 01 26 C5` |
| 读版本 | `14 03 00 15 00 05 96 C8`，ASCII应为XDZ_V2.0.0 |
| 485口2读全部XDZ寄存器 | `02 04 02 00 00 1B B1 8A` |
| 本机读共享采集缓存 | `14 03 00 24 00 08 06 C2` |
| 保存当前模式/参数并重启 | `14 06 00 21 DD CD 43 C0` |
| 切回DTO／HIK | `14 06 00 22 00 00 2B 05`／`14 06 00 22 00 01 EA C5` |

只切换不保存；收到确认后等待约1秒，再查询模式。未采到有效数据也会回复，测量值按零处理，
协议固定字段仍保留；旧协议的低压／低SOC报警派生规则也保留，所以“无数据回复”不保证所有寄存器都是零。

## 电池轮询与模拟回复

交替轮询，每次起发至少间隔1秒；TX完成后响应超时600ms，排队超时2秒，失败后静默600ms。
没有EVE/SZS检测；XDZ固定使用地址05的两组寄存器。必须同时取得两组新鲜数据才能发布缓存，7秒过期。
帧须匹配当前事务的地址、功能、长度及CRC；异常、错误CRC、超时及过早回复不刷新缓存。
配置/维护会暂停轮询，恢复后先等待静默；不会在普通事务完成时清除本机命令队列。

| 步骤 | 发往485口1的查询 | 字段 |
| --- | --- | --- |
| 0 | `05 03 00 12 00 03 A4 4A` | 总电压、有符号电流、剩余容量 |
| 1 | `05 03 00 25 00 06 D5 87` | 温度1、温度2、标称容量、SOC、MOS、保护位 |

串口助手可在收到相应查询、板子TX完成后，模拟回复：

- 步骤0：`05 03 06 0A 50 FB 2E 06 E5 40 15`
- 步骤1：`05 03 0C 0B A5 0B AF 07 D0 00 58 00 03 00 00 E8 92`

按参考换算，对应26.40V、−12.34A、剩余176.5Ah、标称200Ah、SOC88%、25/26℃、MOS均开。
共享本机缓存36～41使用0.01V、0.01A、%、0.01Ah和0.1℃；太阳能42/43为0，XDZ未采太阳能。
XDZ剩余容量取设备实报，**不使用HIK的标称容量×SOC估算**。
容量按旧工程“原值÷10＝Ah”推得单位，设备实测仍需核对；公共16位0.01Ah值超过65535时饱和，
不会溢出回绕。XDZ外部寄存器仍按旧格式保留整数Ah。

## 主机04读取区

地址02；请求固定8字节。支持0x0200～0x021A任意合法连续子区间，最多27项、正常回复最多59字节。
字节序为寄存器高字节在前，CRC低字节在前。

| 地址 | 含义与旧工程换算 |
| --- | --- |
| 0200 | bit7充电MOS、bit6放电MOS |
| 0201 | 保护映射：高温/过流/过充/电量空/低压/低温/短路；低压派生条件仍为电池电压÷10≤250 |
| 0202 | SOC≤30时F401，否则0 |
| 0203 | 剩余容量，整数Ah（设备原值÷10） |
| 0204 | SOC放高字节，低字节0 |
| 0205 | 旧功率公式：((原电压÷10÷10)×abs(原电流÷10))÷10 |
| 0206 | 原电压÷10，0.1V |
| 0207 | 有符号原电流÷10，0.1A，向零截断 |
| 0208～0209 | 0 |
| 020A | 温度1/2分别占高/低字节，带符号整数℃ |
| 020B～0211 | 固定CECE |
| 0212～0216 | 0 |
| 0217～0218 | 原工程单体派生公式：原电压×100÷8，保留16位结果 |
| 0219～021A | 0 |

固定填充、报警规则、功率及单体派生公式均为兼容旧协议，未新增相应硬件测量。
合法读取回复已与参考原函数做37,800次逐字节对比；不复制其越界读取、空指针先解引用等问题。

## 主机10双继电器控制

仅接受起始0425、数量1、字节数2。旧XDZ是低有效控制：写0请求基础GPIO高，写任意非零请求基础GPIO低。
协议适配为公共逻辑请求：XDZ值0→logical 1，XDZ非零→logical 0；再统一应用35反向位和欠压保护。
因此本机14/05的FF00/0000逻辑含义不变，不能把XDZ原始写入值直接当成本机逻辑状态。

| 35配置 | XDZ写0 | XDZ写1或其他非零 |
| --- | --- | --- |
| 0，两路正常 | 两路GPIO高，本机状态1 | 两路GPIO低，本机状态0 |
| 3，两路反向（出厂默认） | 两路GPIO低，本机状态1 | 两路GPIO高，本机状态0 |

混合配置按对应位异或；欠压时本机状态统一覆盖为0，GPIO以保护映射为准。

| 操作 | 指令 |
| --- | --- |
| XDZ写0（正常配置GPIO高） | `02 10 04 25 00 01 02 00 00 F0 55` |
| XDZ写1（正常配置GPIO低） | `02 10 04 25 00 01 02 00 01 31 95` |
| 正常ACK（两种命令相同） | `02 10 04 25 00 01 11 01` |

走公共svc_relay和app_local维护流程，使用当前35映射；欠压期间保持保护覆盖、恢复后应用最新请求。
先回原485口2确认，不重启。按用户确认，XDZ模式下继电器控制只修改RAM，不写继电器页；
同模式下本机14/05控制也不保存继电器状态。保存参数56781／恢复默认52445仍正常写参数页，
但不会顺带保存或迁移继电器记录。DTO/HIK的继电器保存规则不变，已有Flash继电器记录不擦除。
本次只取消XDZ写入，启动读取既有记录仍沿现有逻辑，模式切换仍保留公共RAM状态。
35接线/反向配置仍是参数，需56781保存；本项与继电器动作状态记忆分开。
CRC错、错误ID和不支持功能丢弃；有效帧的非法地址/数量/结构回原功能OR80及旧异常码44。
只允许已实现的0425控制，其他写地址不再像旧代码一样假成功。

## 观察与验收边界

- `g_mode`：active应为2。
- `g_xdz_poll`：sent/received/updates、step/state、timeouts/invalid等。
- `g_xdz`：主机requests、replies_queued、relay_commands、blocked等。
- `g_telemetry`：公共电池缓存；太阳能无效。

临时原生测试覆盖27个集成场景（追加了4种35配置×0/1/FFFF写值及本机05方向对照）：轮询/TX完成/超时/缓存失效、三口切换与保存、版本、
DTO/HIK往返、RAM SN保留、双继电器RAM控制及欠压、XDZ保存参数不写继电器页、DTO/HIK仍保存、队列背压、两路4G配置、三口BootLoad。
这些是软件验证，本轮没有烧录；实际电池字段、端口通信和上位机仍需上板验收。
